

## Начало

Сначала запусти server.py, затем client.py. Для двух пользователей запусти
два экземпляра клиента (или два терминала в папке проекта):

```text
python server.py
python client.py
```

Сервер слушает порт 5555, клиент подключается к 127.0.0.1.
Имя нужно ввести и подтвердить Enter за 15 секунд.
Пустое или занятое имя сервер не принимает.

## Команды

- Обычный текст — сообщение другим пользователям (TEXT).
- /list — список имён в чате (LIST).
- /nick новое_имя — смена имени на том же соединении (NICK).
- /quit — выход (QUIT).
- JOIN отправляется автоматически при подключении.
- ERROR — ответ сервера при ошибке, отображается клиентом как [ошибка].

## Что изменено

1. **protocol.py, ДЗ 1:** вместо фиксированных четырёх байт команды
   заголовок `!II` хранит две длины по 4 байта: команды и payload.
   Затем идут байты команды и байты payload. Команда кодируется в UTF-8.
   ERROR больше не обрезается. Лимит команды — 64 байта, payload — 10 МиБ.
   Проверки работают и при отправке, и перед чтением тела при получении.
2. **client.py, ДЗ 2:** добавлена input_username(). Поток выполняет input(),
   основной поток ждёт queue.get(timeout=15). Это блокирующее ожидание,
   без busy waiting. Поток daemon не мешает завершению процесса по таймауту.
   Ввод имени заканчивается по Enter, не по первому набранному символу.
3. **client.py и server.py, ДЗ 3:** добавлены /nick и NICK. Сервер проверяет
   пустое имя, занятость и UTF-8. Проверка и обновление словаря выполняются
   под clients_lock, чтобы два клиента не заняли одно имя одновременно.
   Успех виден всем в чате; ошибка приходит отправителю как ERROR.
   Повторно выбрать собственное имя разрешено.
4. **Обработка ошибок:** ERRO заменён на ERROR во всех ответах и в клиенте.
   Некорректный кадр сервер отклоняет с ERROR и закрывает соединение,
   а ошибку NICK можно исправить следующим запросом без переподключения.
   Добавлены сообщения об ошибках соединения и закрытие сокета при
   неудачном подключении. Неуспешный JOIN больше не объявляется как выход
   зарегистрированного пользователя. pickle и except Exception не используются.

Комментарии около правок отмечены `ДЗ 1`, `ДЗ 2`, `ДЗ 3` и объясняют логику.
Архитектура осталась прежней: отдельный поток на клиента и словарь имён.
Новый формат требует обновить одновременно сервер и клиент; смысл старых
команд сохранён, но старые версии файлов не понимают новый заголовок.
