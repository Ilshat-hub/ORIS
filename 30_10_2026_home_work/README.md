# Обработка сетевых ошибок и завершение потоков в PyQt6

## Внесённые изменения

Доработан существующий сетевой чат. В `main.py` добавлены обработка сетевых ошибок, уведомление окна о потере соединения и остановка потоков при закрытии приложения. Файл `server.py` не изменялся.

## Обработка потери соединения

В `ReceiveThread` добавлен сигнал `disconnected`, передающий текст причины отключения.

Вызов `self.net.recv()` помещён в блок `try/except OSError`. При сетевой ошибке поток отправляет сигнал и завершает цикл. Также обрабатывается возврат `None`, означающий закрытие соединения.

Сигнал подключён к методу `MainWindow.handle_disconnect()`. Этот метод показывает причину отключения и отключает элементы ввода и отправки сообщений. Рабочий поток не изменяет интерфейс напрямую.

В `SendThread` также добавлена обработка `OSError` при отправке сообщения с уведомлением окна через сигнал.

## Остановка SendThread

Добавлен метод `stop_queue()`, который помещает `None` в существующую очередь:

```python
def stop_queue(self):
    self.queue.put(None)
```

Метод `queue.get()` получает это значение, после чего поток выходит из цикла через `break`.

При закрытии окна вызывается `closeEvent()`. Он отправляет команду остановки, прекращает работу сетевого соединения и закрывает сокет. Это также освобождает принимающий поток от ожидания данных. Затем с помощью `wait()` приложение дожидается завершения обоих потоков и принимает событие закрытия окна.

## Индикатор подключения

Использована существующая надпись `status_label`. При подключении она показывает `Connected to 127.0.0.1:50505`, а при потере соединения - сообщение о причине отключения. Обновление выполняется методом окна, подключённым к сигналам рабочих потоков.

## Выполненные проверки

Вручную проверены:

* запуск сервера и подключение клиента;
* отправка сообщения и его отображение в истории;
* остановка сервера при открытом клиенте;
* изменение надписи и отключение ввода после потери соединения;
* закрытие клиента после отключения сервера.

При выполненных проверках клиент не завершался аварийно и закрывался без зависания.
